# Parser & semantics simulator

A page for stepping through the parser and semantic analysis token by token. You play the lexer.

Open `index.html` in a browser. There is no build step and no server.

- **Send a token**: pick a token type, fill in its value (identifier, number, raw indent) and send it. The *Accepted next* palette lists every token the parser can take at this point. Click one to send it.
- **Token stream**: ◀ ▶ (or Alt+← / Alt+→) step through the tokens. Click a token to rewind to it. Sending a token cuts off whatever followed the current position.
- **AST**: the parser's output, the tree after semantic analysis (types `:Int`, slots `@1`, function ids `fn0`, `INT_TO_DOUBLE`), and the S-expression in the `tests/unit/helpers/ast_test_string.c` format.
- **Blocks & scopes**: the scope owners (DEF, BLOCK, FOR). Blocks still open are highlighted. Each one's symbols show up after EOF.
- **Parser state**: the indent stack, the nonterminal calls the parser is waiting in, the precedence stack, and the tokens after the token layer (block open and block close).
- **Copy as C test tokens** gives the stream as `fake_tokens.h` macros, ready to paste into a unit test.

Example scenarios cover accepted programs, syntax errors and each semantic exit code. `index.html#widening@20` opens a scenario with its first 20 tokens sent (`@end` sends all of them).

## Keeping it in sync

`engine.js` is a JavaScript port of `src/parser.c`, `src/expr_parser.c` and `src/semantics.c`. It is not linked to them, so after changing those files run:

```sh
tools/parser-semantics-sim/verify.sh
```

The script runs every scenario through the real C parser and semantic analysis (through the unit tests' fake token source) and through the simulator, then compares exit codes and AST strings. It needs clang and macOS JavaScriptCore; set `JS=` to use another shell that has `print`.
